- 예상값은 Cross로 이미 틀린값을 가지고 있으며, 점수 차이가 허용오차 이내로 UNDECIDED 판정을 받아 FAIL

### 성능 분석
- MAC연산은 n*n행렬의 각 요소들끼리 곱하고 더하여, 시간복잡도 O(N^2)를 가짐.
- 사이즈 3*3, 5*5, 13*13, 25*25의 시간복잡도 O(N^2)은 각각 9,25,169,625이고
- 출력된 평균연산시간은 각각 0.0016ms, 0.0055ms, 0.0102ms, 0.0342ms로 나옴.
- 사이즈가 커짐에 따라 연산시간도 길어지나, 시간복잡도값과 딱맞게 비례하지는 않는 모습을 보임.
- 컴퓨터 내부적으로 코드 실행과정에서 발생하는 미세한 기본 시간이 상수로 존재하고, 이것이 연산시간에 영향을 준 것으로 생각됨.


## 네이토 사전평가 후 보완한 부분
### 대규모(예:1000x1000) 처리 시 예상 병목
- 연산할 데이터의 크기가 커지면 CPU의 L1, L2 캐시 크기를 초과하여, CPU가 다음 데이터를 찾지 못해 메모리에서 가져올 때까지 연산을 멈추는 캐시 미스 지연(Latency)이 극대화
- 수행할 곱셈과 덧셈이 늘어날수록 코어가 순차적으로 처리해야 하므로 연산 속도가 급격히 떨어짐
### 최적화 방안
- 2차원 배열/리스트를 중첩 반복문으로 수행하는 행렬 계산을 1차원 배열/리스트로 변환하여 수행할 경우, 1차원 배열은 데이터가 메모리에 일렬로 빈틈없이 붙어 있기 때문에, CPU가 다음 데이터를 찾을 때 메모리까지 갈 필요 없이 바로 옆 캐시에서 꺼내 사용할 수 있음. 이를 캐시 히트(Cache Hit)라고 하며 연산 속도가 수십 배 빨라짐.
- 파이썬의 경우 직접 1차원으로 바꿀 필요 없이, 내부적으로 데이터를 1차원 C-contiguous(연속 메모리) 구조로 관리하는 NumPy를 쓰면 자동으로 극한의 최적화가 이루어짐.


### CPU와 NPU의 병목 차이(직렬/병렬 특성)
#### 1. CPU의 병목 특성: 직렬 구조와 연산 지연
- 코드가 복잡해져 조건문(If-Else)이 많아질 때 병목이 발생.

#### 2. NPU의 병목 특성: 대규모 병렬 구조와 데이터 굶주림
- 연산기에 인공지능 모델의 '가중치(Weights)'와 '입력 데이터'를 공급해 주는 DRAM의 전송 속도(대역폭)가 이를 따라가지 못할 때 발생.
- 연산 장치는 준비가 끝났는데 데이터가 도착하지 않아 발생하는 데이터 굶주림(Data Starvation)이 핵심 병목.
